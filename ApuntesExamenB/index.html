Tasca 1 · Sistemas operativos

  • S.O.: software que gestiona todo entre el hardware y el software.
  • Funciones: administrar recursos de hardware, comunicar usuario y máquina, gestionar archivos, dar interfaz visual.
  • Tipos: móvil (Android, iOS), ordenador (Linux, Windows, macOS), servidor (Ubuntu Server, Windows Server).
  • Partes: Kernel, UI (interfaz), Drivers, Sistema de ficheros.

Funciones principales del S.O. (presentación)

  • Gestión de recursos: administra de forma eficiente y segura CPU, memoria y periféricos.
  • Gestión de procesos: ejecuta, para y controla programas y tareas que piden recursos.
  • Administración de memoria: controla la memoria de cada programa para que no interfieran entre ellos.
  • Gestión de ficheros: organiza archivos y directorios en los dispositivos de almacenamiento.
  • Control de dispositivos: usa controladores (drivers) para unificar el acceso al hardware.
  • Seguridad y usuarios: permisos, contraseñas y protección de datos frente a usuarios no autorizados.
  • Interfaz de usuario: entorno visual o de comandos para interactuar con el equipo.

Tasca 5 · Gestión de procesos

  • Proceso: programa en ejecución. Programa: conjunto de instrucciones. PID: identificador único de cada proceso.
  • Servicio: proceso en segundo plano que da funciones al sistema (autenticación, red, impresión, actualizaciones…). Si se detiene uno necesario, pueden fallar el inicio de sesión, recursos compartidos, impresión y servicios dependientes.
  • svchost.exe: proceso muy habitual que ejecuta distintos servicios de Windows. Hay varias instancias, cada una con distinto PID, por eso es normal ver muchos con este nombre.
  • Programa vs proceso: notepad.exe en disco es el programa; notepad.exe ejecutándose es el proceso, y usa CPU, RAM, disco, red…
  • Servicios típicos: DNS Server, DHCP Server, Active Directory Domain Services, Windows Update, Print Spooler. Funcionan aunque nadie interactúe con el servidor.
  • No finalizar procesos del sistema sin saber su función: se pueden perder datos o dejar el sistema inestable.

Servidor con CPU al 95%

Identificar proceso → localizar PID → consultar sus datos (Administrador de tareas / tasklist) → ¿es legítimo? → decidir si se finaliza y justificarlo → proponer solución para que no se repita. Flujo: Identificar → Analizar → Controlar → Solucionar.

Ciclo de vida de un proceso

Creación (el S.O. reserva el PCB) → Preparado / Ready (en memoria, esperando CPU) → Ejecución / Running (tiene la CPU) → Espera / Blocked (aguarda un evento: E/S, disco, entrada del usuario; al completarse vuelve a Preparado) → Finalización / Terminated (acabó o error) → Liberación de recursos (limpia memoria, cierra ficheros y lo elimina de la tabla de procesos).

  • PCB (Process Control Block): guarda la información del proceso (estado, PID, memoria…).
  • Planificador (scheduler): decide qué proceso obtiene la CPU.

Prioridad de los procesos

De mayor a menor: Tiempo real → Alta → Por encima de lo normal → Normal → Por debajo de lo normal → Baja.

Proceso que no responde

1) Identificar el proceso · 2) Consultar CPU y RAM · 3) Comprobar el PID · 4) Finalizarlo si es necesario · 5) Investigar la causa. En un servidor de producción, con cuidado.

Monitorización

  • CPU: procesos que consumen mucho · RAM: mucha memoria · Disco: muchas operaciones de E/S · Red: mucho tráfico.
  • Herramientas en Windows Server: Administrador de tareas y Monitor de recursos.

Tasca 7 · Acceso remoto Client → Server

Pasos

  • 1. Habilitar: Administrador del servidor → Servidor local → Escritorio remoto → «Permitir conexiones remotas a este equipo» + NLA (autenticación a nivel de red: el usuario se autentica antes de conectar).
  • 2. Permisos: Seleccionar usuarios… (grupo Remote Desktop Users). Los Administradores ya tienen acceso implícito. Se añadió a Fermin (no admin).
  • 3. Firewall: puerto 3389 (TCP/UDP); reglas de entrada «Escritorio remoto – Modo de usuario (TCP-In / UDP-In)» habilitadas.
  • 4. Conectar: mstsc (Win+R) + IP o nombre del servidor. Admin: sí · Invitado: no · Fermin: sí (aviso de certificado) · Gavi (sin permiso): no, conexión denegada.
  • 5. Caso práctico: por defecto 2 conexiones administrativas concurrentes; para permitir 4 → directiva «Limit number of connections» = Enabled, 4, y gpupdate /force.

3. Entorno personal

  • Nombre de equipo, zona horaria, idioma, teclado y formato regional (Configuración).
  • Personalizar fondo/tema/inicio/barra: requiere Windows activado.
  • Explorador: Vista → Mostrar u ocultar → Extensiones de nombre de archivo y Elementos ocultos; fijar accesos rápidos.
  • ProgramData está oculta: guarda datos de aplicaciones y configuraciones comunes a todos los usuarios.
  • Usuario estándar: usa apps y cambia sus ajustes; no instala para todos ni cambia configuración importante. Administrador: instala software/drivers, cambia el sistema, gestiona cuentas (UAC pide confirmación). Se crean con lusrmgr.msc o net user.
  • UAC: por defecto avisa solo cuando una app intenta hacer cambios; se puede subir a «Notificarme siempre». Opciones de energía: apagar pantalla tras X minutos o nunca.

5. Fin de soporte de Windows 10

  • Terminó el 14 de octubre de 2025: sigue funcionando pero sin actualizaciones de seguridad habituales (más riesgo de virus y ataques).
  • ESU: actualizaciones de seguridad ampliadas y de pago; ganan tiempo, sin funciones nuevas ni sustituyen la migración.
  • Los 15 equipos (32 bits, 2 GB) no cumplen Windows 11 → mejorarlos, copia de seguridad, probar la migración en uno; ESU como solución temporal.
